# Восстановление итога боя

Контракт согласован 15.11.2026 для PvE и дуэлей в основной онлайн-игре.

- При старте боевая транзакция присваивает контексту случайный `combatId`. Повтор того же запроса старта сохраняет этот идентификатор. Старые открытые контексты продолжают работать без нового поля.
- Edge принимает запись с `combatId` или запрос на чтение результата с тем же ID. Он определяет владельца по токену Supabase Auth. Для совместимости `{ log }` продолжает работать по прежнему протоколу.
- `combat_finish` проверяет ID под блокировкой строки персонажа и вызывает действующий `combat_apply` вместе с административной обёрткой. Изменение прогресса и запись результата коммитятся одной транзакцией. Повтор получает подтверждённый итог и свежую ревизию персонажа, даже если начался другой бой.
- В результат входят исход, награды, фактические потери монет и зелий, повышение уровня и изменение рейтинга в дуэли. Сервер использует краткую запись из `combat_receipts`. Полная копия профиля и запись действий в неё не входят.
- Браузер хранит только ID последнего отправленного боя для текущего аккаунта и время его записи. При загрузке персонажа он запрашивает итог и показывает его отдельным окном. Просмотр убирает локальную отметку. С другого устройства итог можно запросить с тем же ID под тем же аккаунтом.
- Если транзакция ещё не завершилась, сервер отвечает `result_pending`. Для неизвестного, просроченного или чужого ID он отвечает `result_unavailable`. При временной ошибке окно предлагает повторить проверку или перезагрузить игру. Получение результата не запускает повторное начисление.
- Результат доступен **7 суток**. Неотправленная запись действий после закрытия вкладки не восстанавливается. На сервере очистку запускает Cron или настроенный администратором планировщик.

Проверка — `node tests/combat-receipts-test.mjs`. В изолированной базе тестируются старый контекст, обрыв после коммита, перезагрузка, повтор с другого устройства, два одновременных запроса на завершение дуэли, границы аккаунта, списание зелий и монет и истечение срока хранения. Порядок выпуска описан в [инструкции](RELEASE_AND_RECOVERY.md).
