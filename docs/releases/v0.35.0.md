# v0.35.0 — админка тестирования игроков

Панель открывается по `admin.html` или `?admin`. Для поддержки, разработчика, администратора и владельца в меню игры появляется «Управление». Вход использует существующий аккаунт игры; отдельного пароля администратора нет. «Мой персонаж» открывает собственную карточку.

## Возможности

- Игроки: поиск по нику и числовому ID, глава, онлайн, уровень, даты, ковен, устройство и версия последней сессии.
- Карточка: текущая сюжетная цель, подтверждённые события и победы, дары, кошелёк, ресурсы, амулеты, сюжетные предметы и ожидающая добыча.
- Выдача и изъятие любого предмета из каталога, монет и сапфиров; кнопка «Всё» для выбранного предмета, набор припасов. Причина **необязательна**. До подтверждения виден расчёт изменения. Ручная выдача заполняет свободное место, остаток сохраняется в ожидающей добыче.
- Журнал: дата и время UTC+5, игрок, ресурс и хранилище, изменение, до/после, источник, исполнитель, причина. Поиск, фильтры периода, типа, источника и направления; страницы по 50 записей. Номер операции открывает все связанные изменения: например, списание трав и начисление монет при продаже.
- Помощь: лечение, безопасная точка из доступных по сюжету, завершение зависшего боя без награды, завершение уже начатого изучения, восстановление дара по подтверждённому открытию или изучению. Перед изменением сохраняется серверный снимок. Новая игра обнуляет доказательства даров прошлого прохождения.
- Отмена ручного изменения отдельной обратной операцией: только пока прогресс и кошелёк не изменились после исходной операции. История сохраняется; отмена не возвращает персонажа в отменённый бой.
- Поддержка: очередь реальных обращений, назначение/взятие, переписка, заметки команды, шаблоны и решение. Существующие ограничения доступа к чужим назначенным обращениям сохранены.
- Ошибки: отказы игровых действий сервера и отчёты клиента. Клиентские ошибки отмечены отдельно, с данными устройства/версии сессии.
- Статистика: игроки, регистрации, онлайн, главы, остатки валют, оборот по источникам и подтверждённые сервером исходы боёв по типу монстра. Выдачи команды отделены от игрового дохода; начальные остатки исключены из оборота.

## Права

| Роль | Просмотр и обращения | Предметы, монеты, помощь | Сапфиры, отмена |
|---|---|---|---|
| Поддержка | Да | Нет | Нет |
| Разработчик | Да | Игроки с более низкой ролью | Нет |
| Администратор | Да | Игроки с более низкой ролью | Да |
| Владелец | Да | Игроки с более низкой ролью и **собственный персонаж** | Да, включая **собственный персонаж** |

Исключение для собственного владельца относится к ресурсам и помощи. Иерархия назначения ролей, переименования и блокировок не изменена. Сервер заново проверяет роль при каждом запросе. Данные админки закрыты RLS, копии игровых функций находятся в приватной схеме. Прямой вызов `combat_apply` остаётся только у `service_role`.

## Обновление базы

Для базы с актуальной схемой v0.34.3 и установленными миграциями чата/ковенов выполнить **целиком**:

[`supabase/migrations/20261008_test_admin.sql`](../../supabase/migrations/20261008_test_admin.sql)

Миграция повторяемая: персонажи, сумки, кошельки и существующая история сохраняются. Для новой базы порядок такой:

1. `supabase/schema.sql`.
2. `20261004_game_chat.sql` и `20261004_chat_roles_v2.sql`.
3. `20261005_chat_amulet_catalog.sql` и `20261006_chat_catalog_ch2.sql`.
4. `20261007_covens.sql` и `20261008_coven_cycles.sql`.
5. `20261008_test_admin.sql`.

После будущего повторного применения `schema.sql`, миграции чата или ковенов **снова выполнить миграцию админки последней**: она обновляет приватные копии изменившихся игровых функций и восстанавливает обёртки. Это проверяется тестом. В каноническую схему админка не вставлена, поскольку использует отдельную схему ролей чата.

История сапфиров и прежних ручных выдач импортируется из существующих журналов. Для остальных ресурсов записываются начальные остатки с нулевым изменением. **Не записанные раньше движения восстановить невозможно.** Полный журнал и статистика боёв начинают накапливаться после установки миграции. Сбор, торговля, крафт, награды, ковены, арена, расходники, изучение и изменения сумки записываются транзакционно.

Новая публикация Edge Function `combat` именно для админки не требуется: её правила и протокол не менялись. Используется функция боя актуальной базовой версии игры. До установки SQL админка показывает сообщение об отсутствии миграции.

Помощь активному игроку повышает отдельную ревизию поддержки. Устаревшее сохранение не перезаписывает исправленную позицию; после следующего ответа сервера игра предлагает продолжить с новым состоянием. Выдачи ресурсов обновляются при обычной синхронизации.

## Проверка

`npm test`, `npm run test:chat`, `npm run test:admin`, `npm run build`, `npm run check:bundle`.

SQL-тесты выполняются в изолированном PostgreSQL через PGlite: повторная миграция, владелец самому себе и пустая причина, иерархия ролей, закрытые таблицы/функции, защита повторов и конфликтов, атомарность, сумка/ожидающая добыча, обычный сбор/продажа/крафт, настоящий повтор боя, помощь и обратные операции, безопасные точки, повторная установка канонической схемы. Браузерный тест `npm run test:admin:browser` работает с этой же настоящей SQL-миграцией на 1280×900, 390×844, 360×800; проверяет формы, журнал, поддержку, все разделы, крестик/Escape и отсутствие ошибок/переполнения страницы. Browser plugin в среде отсутствует; используется Playwright/Chromium.

Продуктивная база не изменялась: SQL устанавливает владелец.
