# Witch RPG — первый играбельный прототип (graybox)

**Текущая версия: v0.9.3** — исправление v0.9.2: кнопки ответов в диалогах (раздел «v0.9.3» в конце); выбор героя — раздел «v0.9.2». ⚠ Рисунки колдуна пока **временные** — релиз только после замены финальными (см. «Временная графика»). Предыдущие: «v0.9.1» (исправление действий сервера), «v0.9.0» (сюжет, мана, зелья).

Мобильная браузерная RPG на Phaser 3, портрет 9:16 (720×1280, FIT). Всё нарисовано примитивами, финального арта нет.
Единственный источник правды — `Witch_RPG_All_Technical_Specifications.docx`. Числа баланса взяты оттуда и лежат только в `src/config/*`.

## Запуск

```bash
npm install
npm run dev        # vite --host: откройте адрес из консоли, с телефона тоже (та же сеть)
npm test           # логические тесты боя и прогрессии (Node, без браузера)
npm run build      # статическая сборка в dist/
```

Параметры URL:
- `?reset` — начать с чистого сохранения.
- `?debug` — физические хитбоксы, лог событий в консоли, `window.__witch` (services). В debug клавиша **F** мгновенно завершает исследование Телекинеза II.

Сохранение хранится в `localStorage`. Сброс также есть в Сумке → «Сбросить прогресс».

## Управление

| Действие | Клавиатура | Мышь / тач |
|---|---|---|
| Движение | WASD / стрелки | плавающий джойстик (зажать и тянуть) или тап по земле |
| Взаимодействие с объектом в фокусе | E / Space / Enter | кнопка контекста или тап по объекту (герой сам подойдёт) |
| Способности (TK / Огонь / Астрал) | 1 / 2 / 3 | кнопки нижней панели |
| Смена цели в бою | Q / Tab | тап по объекту или врагу |
| Сумка | B / I | кнопка «Сумка» |
| Журнал заданий (v0.8) | J | значок книги у цели вверху или тап по плашке цели |
| Зелья в бою (v0.8) | 4 / 5 / 6 | круглые кнопки слева над способностями |
| Закрыть окно | Esc | кнопка в окне |

Точность нигде не нужна: у объектов крупные радиусы, тап ищет ближайший объект с запасом.

## Тестовый маршрут (что должно произойти)

1. **Дом ведьмы (A).** Книга → открывается Телекинез I (`unlock_telekinesis_1`).
2. **Стартовая поляна (B).** Сдвиньте камень Телекинезом: тайник и `first_world_interaction`. Притяните лунное растение. Корни у западного прохода → «Нужен Огонь» (`fire_required_01`).
3. **Лесная тропа (C) → Первая боевая поляна (D).** Лесной падальщик: обучающий бой (`combat_intro_01`), около 20–30 с. Герой бьёт сам; бросайте предметы Телекинезом и прерывайте рывок, когда появляется предупреждение.
4. **Лунный алтарь (E).** `lunar_quest_start`: соберите 3 лунных пламени (притянуть, сдвинуть камень, победить стража `lunar_guard_01`). Затем `lunar_quest_complete` → исследование Телекинеза II (`telekinesis_2_start` → `telekinesis_2_complete`).
5. **Тяжёлый валун.** Его может сдвинуть только TK II → `heavy_path_open`, путь на север.
6. **Древний круг Огня (H).** Открывается Огонь I (`unlock_fire_1`). Подожгите факел или куст: `fire_gate_open`.
7. **Возврат к корням (B).** Сожгите их: открывается Новая часть леса (J).
8. **Поляна Лесного Стража (K).** Сильный враг (`forest_guardian_01`): броня, тяжёлый удар. Бросок тяжёлого камня прерывает удар, кристалл снимает броню. Победа → `guardian_defeated`.
9. **Древние ворота (L).** Печать не реализована: `SEAL_REQUIRED` (`seal_required_01`) → экран «Прототип пройден» (`prototype_complete`).

После боя мир сохраняется: открытые пути, побеждённые враги, сдвинутые и сожжённые объекты. При поражении герой возвращается в safePoint зоны и теряет часть монет; враг остаётся.

## Архитектура

```
src/
  main.js                 конфиг Phaser, список сцен
  services.js             общие сервисы: bus, state, quests, abilities, input, mode
  config/                 ВСЕ числа и раскладка
    game.config.js        экран, камера, игрок, управление, слои, цвета, сохранение
    balance.hero.js       статы героя, XP, уровни
    balance.abilities.js  Телекинез I/II, Огонь I, Печать: урон, мана, перезарядки, weight_class
    balance.enemies.js    враги, их атаки, касты, броня, арены
    balance.progression.js награды, исследование TK II, стоимость
    events.js             ключи событий (EV) и шаги квестов
    world.layout.js       зоны, коллизии, декор, объекты, враги
    assets.manifest.js    файлы ассетов и размеры на экране
  state/
    GameState.js          Save/GameState (чистый JS, localStorage)
    EventBus.js           шина сообщений
    QuestFlags.js         Quest/Event flags, текущая цель
  systems/
    AbilitySystem.js      открытие и уровни способностей, кулдауны, исследование
    CombatManager.js      математика боя (чистый JS, покрыт тестами)
    InteractionSystem.js  фокус, маркеры, выбор объекта по тапу
    InputController.js    клавиатура → общее состояние ввода
  objects/
    Player.js             герой: движение, walkTo, анимации
    InteractiveObject.js  базовый объект + книга, сундук, подбор, алтарь, круг Огня, ворота
    TelekinesisObject.js  push/pull, проверка веса
    FireObject.js         normal → burning → destroyed
    EnemyTrigger.js       враг в мире, запуск боя
    Enemy.js              враг в бою (чистая логика)
  scenes/
    BootScene → PreloadScene → ExplorationScene + UIScene (параллельно)
    CombatScene           запускается поверх, ExplorationScene спит и потом просыпается
tests/run-tests.js        проверки Combat Math и прогрессии
```

Как это связано: сцены не знают друг о друге напрямую. Они общаются через `services.bus` (EventBus) и через провайдеры в `registry` (`hudProvider`, `abilityProvider`), которые UIScene читает каждый кадр.

Чтобы добавить объект: допишите запись в `world.layout.js` (`kind`: `telekinesis` / `fire` / `chest` / `pickup` / …). Новый тип: класс-наследник `InteractiveObject` плюс строка в `OBJECT_CLASSES` в ExplorationScene.

## Замена ассетов

1. Положите PNG в `public/assets/...`.
2. В `src/config/assets.manifest.js` → `ASSET_FILES` замените `null` у нужного ключа на путь.
3. Размер на экране задаётся в `DISPLAY_SIZE`. Pivot — нижний центр (origin 0.5, 1).

Ключи с `null` рисуются graybox-генератором в PreloadScene. Если файл не загрузится, тоже будет placeholder.

## Допущения и адаптации (документы их не определяли или противоречили друг другу)

- Пороги XP по уровням и статы `young_scavenger` придуманы и лежат в конфиге.
- «Лесной Страж» (зона K) использует числа Stone Guardian. Полноценный босс вне scope.
- Магия вне боя не тратит ману.
- Огонь открывается событием мира (Круг Огня), а не 5-м уровнем героя. Так требует маршрут.
- Пассивка 4-го уровня не реализована.
- В первом бою Огня нет: только TK и автоатака.
- Исследование TK II длится 5 минут (режим `live`; быстрый режим `prototype` — 60 с, `balance.progression`). `lunar_quest_complete` выдаёт ресурсы на исследование.
- Интервал обычной атаки Стража — 4.5 с. В Combat Math интервал не задан. При 3 с и HP героини 138 даже аккуратная игра заканчивалась поражением. Спам кнопок без механик по-прежнему проигрывает.
- Древние ворота дают финал только после `guardian_defeated` (поле `requiresEvent` в `world.layout.js`).
- Добавлены служебные ключи `lunar_guard_01` и `heavy_blocked_01`.
- Печать, рынок, ковены, PvP, магазин, кастомизация и прочее не делались: так требует ТЗ.

## Проверка

Проект собран на Phaser 3.90 (`vite build`) и пройден целиком в headless Chromium. В консоли не было ни одной ошибки.

Результат автопрохождения:
- Все 15 ключей событий сработали в порядке маршрута; текст цели меняется на каждом шаге.
- Бои: Лесной Падальщик — победа за 26.5 с, Молодой Падальщик — 16 с, Лесной Страж — 43.7 с.

- Управление работает: WASD и стрелки, джойстик (перетаскивание), тап по объекту (герой подходит и взаимодействует), тап по земле, Enter, а в бою клавиша 1 и нажатие на кнопку Телекинеза.

## v0.3.1 — анимации героини

Пока нет покадровых спрайтов, героиня оживлена процедурно поверх трёх статичных поз (`hero_down/up/side`). Когда появятся настоящие кадры, меняется только адаптер: поза (`HeroAnimator`) и конфиг останутся.

- **Покой** — лёгкое «дыхание». **Ходьба** — подскок, вытягивание в воздухе, сплющивание при касании земли, покачивание и наклон вперёд при движении вбок; переход покой ↔ ходьба плавный.
- **Касты** различаются по магии: Телекинез (`telekinesis`, `seal`) — лёгкий подъём с отклонением назад; Огонь (`fire`) — замах и рывок вперёд; автоатака (`auto`, только бой) — короткий выпад. Направление рывка зависит от взгляда: вбок — по горизонтали, вверх/вниз — по вертикали.
- **Удар по героине** — вспышка заливкой, дрожь, сплющивание; сильный удар (`strong`) на 60% сильнее и дольше. **Поражение** — героиня падает, остаётся лежать и полупрозрачна.
- **Тень** уменьшается в подскоке.
- Файлы: `src/config/hero.anim.js` — все числа и ключевые кадры; `src/systems/HeroAnimator.js` — чистая логика без Phaser (покрыта тестами); `Player.js` и `CombatScene.js` — адаптеры.
- В исследовании у `Player` теперь два объекта: `sprite` — невидимое физическое тело (камера, коллизии), `view` — рисуемая и анимируемая картинка. Так смещения анимации не попадают в физику.
- API: `player.castAt(x, y, kind)`, в бою `heroAnim.playCast(kind)`, `playHurt(strong)`, `playDeath()`.
- Анимации идут по реальному времени, а не по `timeScale`, поэтому не замедляются в обучающем слоумо.
- Не проверено в браузере: визуальная оценка амплитуд (подскок, наклон, дрожь) и производительность на телефоне. Все амплитуды регулируются в `hero.anim.js`.

## v0.4.0 — интерфейс

Интерфейс переделан по Visual Style Guide: тёмное дерево, пергамент, тонкое золото, угловые украшения, лунные символы, цветовые акценты магии. Функция важнее декора — читаемость текста и размер зон нажатия не пострадали.

- **Рисование без файлов.** Панели, кнопки, «жемчужины» способностей, полосы HP/маны/опыта, нижняя панель и виньетка рисуются на Canvas 2D (`src/ui/uiPaint.js`, чистые функции без Phaser) и попадают в Phaser как текстуры (`src/ui/widgets.js`). Текстуры рисуются в 2× и кэшируются по ключу; временные (окна) освобождаются при закрытии.
- **Токены** — `src/config/ui.config.js`: цвета дерева и золота, градиенты полос, радиусы, тень текста, размеры орбов. Стиль меняется там.
- **Шрифт** — Philosopher (кириллица) с Google Fonts, запасной Georgia. `loadUIFont()` ждёт не дольше 2 с, потом игра стартует в любом случае. Офлайн шрифт не загрузится — будет Georgia.
- **Экраны:** HUD (квест-панель, медальон героини с уровнем, полосы, монеты и осколки), нижняя панель с кнопками способностей и кнопкой действия, всплывающие подсказки, обучающий пузырь, окна (пауза, сумка, изучение дара, настройки, сброс, финал), главное меню, бой (полоса врага, предупреждения).
- **Виджеты:** `addPanel`, `addButton` (нажатие срабатывает на отпускание внутри кнопки), `addOrb`/`setOrb`, `UIBar` (`setFraction`), `drawPlate`.
- **Сумка** показывает названия врагов вместо id.

## v0.5.0 — аккаунты, редактор карты, дороги и вода, коллизии

### Коллизии

Раньше физическое тело было только у ключевых объектов и у больших блоков леса, а камни, кусты, грибы, фонари и отдельные деревья были лишь картинками, через них можно было пройти. Теперь у каждого объекта есть «след» у основания (`src/world/propDefs.js`, поле `solid`): герой ходит за кроной дерева, но не проходит сквозь ствол, камень, куст, гриб или столб. Цветы, камыш, свечи, следы когтей и мостик проходимы. Список препятствий собирает `src/world/solids.js`: и сцена, и тесты берут его оттуда.

### Дороги и вода

Дороги и ручей — плавные кривые с неровными краями (`src/config/world.terrain.js`, форма строится в `src/world/terrain.js`, рисует `src/world/terrainPaint.js`), а не прямоугольники. Точки и ширину можно менять в `world.terrain.js` или в редакторе (см. v0.7.0). Ручей по-прежнему перекрывает проход между западным и восточным лесом, дороги проходят через узкие места сюжета. Это проверяет `tests/world-test.js`.

### Расстановка и редактор карты

- Все 984 объекта мира лежат в данных (`src/config/world.props.js`, создан `node tools/world/bake.mjs`), поэтому их можно двигать. Не запускайте `bake.mjs` после правок вручную: он перезапишет файл.

## v0.6.0 — онлайн-аккаунты: сервер — источник правды

Игра работает как браузерная онлайн-RPG: Phaser — клиент, а персонаж и прогресс живут на сервере (Supabase) и принадлежат постоянному `user_id`. Двух сохранений («на устройстве» и «в облаке») больше нет, окна выбора сохранения и кнопки «отправить в облако» удалены вместе со старым кодом.

### Как это выглядит для игрока

- **Первый запуск:** «Новая игра» → «Выбор героя» → «Как продолжить?»: «Играть как гость», «Создать аккаунт», «У меня уже есть аккаунт». На стартовом экране также есть «Войти».
- **Гость** — настоящий пользователь сервера (анонимный вход Supabase) со своим `user_id` и персонажем. Ни почты, ни логина, ни пароля игра у него не спрашивает. После перезагрузки страницы или закрытия браузера вход восстанавливается сам, новый гость не создаётся.
- **Аккаунт** — это никнейм и пароль, почты нет. Ник одновременно имя аккаунта, логин и имя персонажа. 3–20 символов: буквы, цифры, `_`. Латиница или кириллица, но не вперемешку, чтобы «Dmitry» с русской «у» не выглядел как чужой ник. Регистр не важен: `Dmitry` = `DMITRY`, при этом показывается написание игрока.
- **Гость → аккаунт:** «Пауза → Профиль (гость) → Создать аккаунт». Тот же `user_id` получает ник и пароль, персонаж, уровень, инвентарь и задания остаются.
- **Вход с другого устройства:** «Войти» → ник и пароль → тот же персонаж со всем прогрессом. При ошибке одно сообщение: «Неверный никнейм или пароль.»
- **Профиль игрока:** ник, уровень, «✓ Прогресс сохранён» / «Сохранение…» / «Нет соединения», дата регистрации, время в игре; «Сменить пароль», «Выйти», «Закрыть». Выход закрывает вход только на этом устройстве, данные аккаунта не трогает.
- **Профиль гостя:** уровень, пояснение и «Создать аккаунт». «Войти в другой аккаунт» тоже есть, но с предупреждением, что гостевой персонаж станет недоступен.
- **Смена ника** не сделана сознательно (ТЗ, п. 19): ник — это логин, и надёжная смена требует отдельной работы. `user_id` от ника не зависит, поэтому добавить её позже можно без переделки данных.
- **Восстановление пароля** без почты невозможно, форма регистрации об этом предупреждает.
- **Нет связи:** окно «Нет соединения · Пытаемся восстановить соединение с сервером… · Повторить». Пока оно открыто, игра и бой стоят. Изменения ждут в памяти и уходят, когда связь вернётся. Параллельного локального сохранения нет.

### Как устроено

- **База** (`supabase/schema.sql`, запускается повторно): `profiles` (ник, нормализованный ник с уникальным индексом, герой, даты, `last_seen_at`), `player_progress`, `player_inventory`, `player_abilities`, `player_quests`, `player_world`. Всё привязано к `user_id`, ник нигде не служит ключом. Паролей в таблицах нет: их хранит Supabase Auth (bcrypt).
- **Запись только через функции.** Клиент может читать свои строки (RLS `user_id = auth.uid()`), а писать — только вызывая `create_player`, `get_player`, `sync_player`, `reset_player`. Прямые `insert`/`update` в таблицы запрещены всем, включая владельца.
- **Автосохранение без «сейва целиком».** После каждого `state.save()` игры клиент считает, что изменилось (`src/cloud/playerModel.js`), и отправляет только разницу: важное через 0,6 с, позицию и время игры раз в 15 с, плюс при сворачивании вкладки. Сервер сливает изменения в одной транзакции под блокировкой строки игрока: счётчики меняются дельтами, уровень, опыт и уровни даров только растут, события и пути только добавляются. Поэтому два устройства одного игрока не затирают друг друга.
- **Повтор без двойного начисления:** у каждой отправки есть id, и повтор после потерянного ответа сервер не применяет второй раз.
- **Доверие клиенту.** Уровень сервер считает сам по опыту (таблица порогов). За одно сохранение принимается не больше 1000 опыта, 500 опыта дара, 500 монет и 50 штук других предметов. Тратить можно сколько есть, уйти в минус нельзя. Подделка «монет = 999999999» не пройдёт. Следующий шаг в сторону полной серверной экономики: награды за события и врагов выдаёт сам сервер по своей таблице, а клиент только сообщает «победил врага X».
- **Вход по нику.** Supabase Auth умеет входить только по почте или телефону, поэтому у каждого ника есть служебный адрес `u<sha256(ник)>@players.witch-rpg.invalid`. Игрок его никогда не видит, писем на него не бывает, домен `.invalid` зарезервирован и ни у кого не существует. Игра вычисляет этот адрес из ника при входе.
- **Регистрация** проходит через Edge Function `account` (`supabase/functions/account/index.ts`). Supabase не даёт анонимному пользователю пароль без подтверждённой почты. Функция работает на сервере с ключом `service_role` и делает три шага: записывает ник (уникальность гарантирует индекс базы, при гонке двух «Дмитриев» проходит ровно один), выдаёт тому же `user_id` служебный адрес с паролем и сразу их подтверждает. Если второй шаг не удался, ник освобождается.
- **На устройстве** хранится только токен входа (`witch_rpg_auth_v2`) и настройки. Пароль не сохраняется.
- **Код:** `src/cloud/PlayerSession.js` (гость, регистрация, вход, выход, загрузка, автосохранение, «Нет соединения»), `src/cloud/api.js` (Supabase на чистом `fetch`), `src/cloud/nickname.js`, `src/ui/accountUI.js` (HTML-окна, чтобы на телефоне работала клавиатура и менеджер паролей), `src/scenes/HeroSelectScene.js`, `src/config/heroes.js`.
- **Режим разработки:** если сервер не настроен (пустые `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`), игра работает без аккаунтов с прогрессом в этом браузере, и меню прямо пишет «Режим разработки». Так же запускаются автотест маршрута и редактор карты.

### Подключение сервера (один раз)

1. Создайте проект на supabase.com.
2. **SQL Editor** → New query → вставьте `supabase/schema.sql` → Run. Схема ставится и поверх v0.5: старая таблица `saves` переименовывается в `legacy_saves`, а не удаляется.
3. **Authentication → Sign In / Providers:** включите **Allow anonymous sign-ins** (гости) и **Email** (через него идёт вход по нику). **Confirm email** можно не трогать: функция подтверждает служебные адреса сама. Для защиты от массового создания гостей Supabase советует включить CAPTCHA, но игра её пока не передаёт, поэтому включать рано. Стандартный лимит — 30 гостей в час с одного IP.
4. **Edge Functions** → Deploy a new function → имя **account** → вставьте `supabase/functions/account/index.ts` → Deploy. Ключ `service_role` функция получает от Supabase сама, в игру он не попадает.
5. **Project Settings → API:** скопируйте Project URL и ключ `anon` (или `publishable`). Оба публичные.
6. **GitHub** → Settings → Secrets and variables → Actions → **Variables:** `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Затем Actions → Deploy to GitHub Pages → Run workflow.
7. Если меняете домен служебных адресов, задайте одно и то же значение в переменной функции `LOGIN_EMAIL_DOMAIN` и в `VITE_LOGIN_EMAIL_DOMAIN`. Иначе вход по нику после регистрации не пройдёт (игра пишет об этом в консоль).

## v0.7.0 — редактор правит дороги, реку и стены

В редакторе (`?edit`) сверху три вкладки: **Объекты** (как раньше), **Дороги и река** и **Стены**. Всё, что вы там изменили, сохраняется в том же черновике и в том же файле `world.edits.js`.

### Дороги и река

- Каждая дорога и ручей — линия из точек. Белые кружки на карте — точки; крайние крупнее. Тяните точку, чтобы выгнуть линию. Контур выбранной линии (как она будет выглядеть) обводится жёлтым и считается тем же кодом, что и в игре. Сама карта перерисовывается, когда вы отпускаете палец.
- **Кривые стыки.** Включённый **Магнит стыков** прижимает конец дороги к другой дороге (сначала к её точке, потом к оси). Кнопка **Примкнуть к дороге** делает то же для выбранного конца одним нажатием (ищет ближайшую дорогу в 500 пикселях). **Сгладить** выравнивает изгибы линии, концы остаются на месте.
- **Пустой клочок без дороги.** Выберите конец ближайшей дороги и нажмите **＋ Точка** (продолжает линию в ту же сторону), потом перетяните новую точку куда нужно. **＋ Точка в начале** делает то же в начале. Коснувшись линии между точками, можно выбрать отрезок, и **＋ Точка** вставит изгиб по центру. Целую новую дорогу можно добавить кнопками **＋ Тропа** и **＋ Каменная**; водоём — **＋ Водоём**.
- **Шире** и **Уже** меняют ширину дороги, берег ручья и размер водоёма. **Убрать всю линию** удаляет её (отмена вернёт).
- Вода по-прежнему непроходима, и её коллизия пересобирается вместе с формой. Ручей запирает проход между лесами: если вы его сдвинули или убрали, **Проверить проходимость** покажет, что «за воротами» стало достижимо в обход. Деревья и камни, расставленные раньше, сами не двигаются: если дорога прошла через дерево, переставьте его во вкладке «Объекты».

### Стены

- Вкладка **Стены** показывает все прямоугольники коллизий (стены дома, руины, лесные блоки, мебель): тяните, чтобы двигать, квадратики по краям меняют размер. Кнопки: **↔ ±** и **↕ ±** (шаг — сетка или 16), копия, удаление, **＋ Добавить** (тип: стена, руины, лес, мебель).
- «Лес» — это непроходимый блок. Он закрывает проход, но сами деревья в нём ставятся во вкладке «Объекты».
- Для файла каждая базовая стена получила номер `c0, c1…` по порядку в `COLLIDERS`. Не меняйте порядок и не вставляйте стены в середину `world.layout.js`: правки привяжутся не к тем стенам. Новые стены получают `cn001…`, дороги — `rd001…`, водоёмы — `wt001…`.

### Что в файле

В `world.edits.js` к прежним `props`, `add`, `pos` добавились необязательные разделы `roads`, `waters`, `cols`: `{ id: полное описание | null }` (изменено или добавлено, либо `null` — убрано). Если вы ничего не меняли в дорогах и стенах, файл остаётся прежним. Старые черновики и файлы читаются как раньше. Игра, тесты и `tools/world/render-map.mjs` берут дороги, воду и стены с правками.

### Проверка

- `tests/world-test.js`: применение и вычисление правок, сохранение файла, геометрия точек, магнита и ручек, форма соседних дорог не меняется после удаления одной.
- `tests/editor-test.mjs`: настоящий `MapEditor` на заглушках сцены и браузера — выбор, перетаскивание, магнит, сетка, добавление и удаление точек, ширина, новые линии и стены, отмена и повтор, черновик, проверка проходимости после правки стены.
- **Не проверено:** редактор в настоящем Phaser и на телефоне (перетаскивание пальцем, нажатия на мелкие кружки, скорость перерисовки при отпускании). Перерисовка рельефа — те же куски 512×512, что и при загрузке игры, поэтому небольшая задержка при отпускании возможна.

## v0.8.0 — «Контент и взаимодействие»: мир оживает

Цель: первые 20–30 минут стали понятнее, живее и атмоснее. Новой карты, нового большого дара, большого крафта и тяжёлой социальной системы нет; главный маршрут (14 шагов) не изменён, серверная схема не менялась.

### Что появилось

- **Цель и журнал.** Вверху всегда видна текущая цель; под ней — активное побочное задание. Журнал (значок книги или клавиша **J**) показывает цель главного пути, активные, доступные и выполненные побочные задания с наградами и подсказками, где искать. Если игрок стоит на месте, героиня «думает вслух» (через 45 с, потом каждые 40 с); после двух подсказок на краю экрана появляется стрелка к цели. Важные интерактивные объекты мягко подсвечиваются вблизи. После Огня героиня напоминает про чёрные корни у дома, включается стрелка, а Мирра подсказывает то же в разговоре. Всё настраивается в `config/guidance.js`.
- **5 ресурсов:** лунная трава, лунный осколок, лесные грибы, древесная смола, рунная пыль (`config/resources.js`). Источники: сбор руками (трава, грибы, смола, пыль, кристалл; после сбора вырастают заново через 2.5–7 минут), Телекинез (лёгкая рунная плита → пыль), тайники и сундуки, награды заданий, сжигание колючих зарослей (→ смола). Сбор сопровождается позой героини, вздрагиванием растения, искрами, взлетающей иконкой и звуком.
- **Ресурсы нужны.** Телекинез II теперь требует ещё лунную траву ×2 и рунную пыль ×1; нехватка показывается в окне изучения и в подсказках. Эти два предмета не «добираются» автоматически при списании (`noTopUp`), остальное как раньше.
- **Алхимия.** Котёл в доме ведьмы (`config/recipes.js`): *настой жизни* (трава ×2 + гриб), *лунный эликсир* (трава + пыль), *смоляная склянка* (смола ×2 + пыль). Зелья используются в бою круглыми кнопками (клавиши 4/5/6): лечат, возвращают ману или поджигают врага. Не больше 4 зелий за бой.
- **4 NPC** (`config/npcs.js`, реплики по ходу прогресса — `config/dialogues.js`): Мирра (хозяйка, учит алхимии), Веда (травница, поляна), Горан (охотник, лагерь на тропе), Селена (дух алтаря). Реплики из 2–5 строк, выбор ответа, значок «!» (есть новое) и «?» (задание в процессе), NPC поворачиваются к игроку, подпрыгивают при встрече. Окно диалога с портретом и посимвольным вводом; тап пропускает печать.

### Допущения

- **Сервер не менялся:** ресурсы и зелья — обычные счётчики инвентаря; прогресс заданий не хранится отдельно, а считается по событиям `sq_<id>_start/_done`, сумке и победам над врагами. Реплики, виденные игроком, хранятся как метки в `tutorial` (`dlg:<id>`, `hero:<id>`).
- **Сбор возобновляется** (время хранится в `worldObjects`), чтобы игрок не застрял без нужного ресурса.
- Падальщик Горана (`scavenger_02`) появляется только после согласия; без принятия задания в мире его нет.
- Зелье в бою — одно действие без перезарядки, но за бой можно выпить не больше 4 зелий (`POTION_BATTLE_LIMIT`). Здоровье после боя и так сбрасывается, поэтому зелья важны только внутри боя.
- Новый арт — векторно-рисованный (PIL), единый по стилю с остальным; портреты и спрайты NPC можно заменить файлами с теми же именами.
- **Не проверено:** настоящий рендер в Phaser на телефоне (расположение портрета и пузырей реплик, частицы, анимации); тесты работают на заглушках Phaser.

### Исправление deferred actions

`DialogueSystem.finish()` завершает разговор и сохраняет прогресс, но больше не выполняет `pendingAfter`. `UIScene.closeDialogue()` уничтожает диалог, очищает `this.modal` и `services.modalOpen`, затем вызывает `DialogueSystem.flushAfterClose()`. Очередь извлекается и очищается до отправки команд, поэтому повторное закрытие не открывает окно дважды.

`tests/ui-smoke.mjs` проверяет реальные ответы из конфигурации: Мирра → «Сварить зелье», «Открыть журнал», «Покажи котёл»; Селена → «Открыть алтарь». ### Общие HP и мана, восстановление

- Одни запасы для мира, боя, HUD, профиля и сумки (`src/state/vitals.js`, поля `hp` и `mana` в сохранении; `null` — «полный», как раньше у `hp`). Бой начинается с текущих значений и сразу пишет изменения обратно. Значения всегда 0…максимум уровня, без `NaN`. Новый уровень не даёт скрытого полного восстановления.
- Восстановление вне боя — только во время активной игры: HP 1/с, мана 0,5/с, в доме Мирры (зона A) мана 2/с. Огромный кадр (скрытая вкладка) обрезается до 0,25 с. В бою HP само не восстанавливается, мана — прежние 4/с (один механизм).

### Победа, поражение и «Сразиться снова»

- **Победа:** награды и уровень как раньше, затем HP = новый максимум; мана — фактический остаток. Экран: «Победа! Здоровье полностью восстановлено» и остаток маны.
- **Поражение:** HP = 20% максимума (минимум 1), мана — остаток, штраф не больше 5 монет (показывается фактический). **Героиня остаётся рядом с тем же врагом, на точке перед началом боя** (координаты запоминаются при старте боя в `worldObjects['enc:<id>']`, не из автосохранения). К `safePoint` не переносится. Текст: «Бой проигран. Вы остались рядом с противником…».
- После поражения этот враг больше не нападает сам — ни через время, ни после ухода и перезагрузки. Над ним — кнопка **«Сразиться снова»** (обычный тап, кнопка действия). При HP ниже 40% сначала предупреждение с текущим HP: «Подготовиться» / «Всё равно сразиться». Бой запускается ровно один раз. Победа снимает это состояние; другие враги ведут себя как раньше.
- **Перезагрузка посреди боя** = отступление рядом с тем же врагом: попытка помечена до старта боя, после загрузки — правило ручного повтора, без штрафа и без награды; HP не ниже 20% (во время боя запасы сохраняются раз в 3 с, поэтому полный запас перезагрузка не вернёт).

### Зелья, лечение, стартовый набор

| Предмет | Эффект | Где |
|---|---|---|
| Настой жизни | +45% HP (до максимума) | в бою и **из сумки** |
| Лунный эликсир | +60% маны (до максимума) | в бою и **из сумки** |
| Смоляная склянка | 45 урона + горение 6/с 4 с | только в бою |

- В сумке у восстановительных зелий кнопка **«Выпить»** (при полном запасе — «Полно», ничего не тратится; восстанавливается только недостающее). Зелья вне боя не тратят лимит боя (4 за бой — без изменений). Сумка, котёл и Мирра объясняют, когда что применять.
- **Стартовый набор:** после первого дара Мирра сама подзывает героиню и даёт по одному Настою жизни и Лунному эликсиру — один раз на персонажа.

Не хватает монет — ничего не списано, подсказка про бесплатное восстановление и настой. Ману эта кнопка не лечит.
- Лечение и стартовый набор проверяет и применяет **сервер одной операцией** (`player_action`, ниже): списание при нехватке монет невозможно, повтор после обрыва связи не даёт второго лечения или второго набора.

## v0.9.1 — исправление: стартовый набор и лечение у Мирры

**Ветка:** `claude/fix-v0.9.1-player-action`. **Бэкап до изменений:** `backup/v0.9.0-before-v0.9.1` → `6583aec` (merge v0.9.0). Механика и баланс не менялись, схема Supabase — та же, что в v0.9.0 (SQL выполнять не нужно).

### Что было

На сервере (production) при получении стартового набора и при лечении игра писала «Нет связи», а во вкладке Network была пачка `rpc/sync_player` со статусом 200 и ни одного `rpc/player_action`.
Причина — в клиенте: `PlayerSession.runAction()` перед действием вызывал `flush()`, а `flush()` считал успехом только состояние «несохранённых изменений не осталось совсем». Пока ждали ответа сервера, мир продолжал жить (время игры каждый кадр, восстановление HP и маны, в доме Мирры — быстрее), поэтому после каждого ответа оставалась новая разница, `flush()` отправлял ещё раз, после 5 проходов сдавался с `false`, и `runAction()` превращал это в `reason: 'network'`, не вызывая `player_action`. Заодно обычное автосохранение во время игры тоже отправляло до 5 `sync_player` подряд.

### Что исправлено

- **Мир стоит, пока сервер выполняет действие** (`services.actions.busy`): не идут время игры и восстановление HP/маны, героиня не двигается, новые игровые события не происходят (`ExplorationScene.canAct()` учитывает действие сервера; покадровые изменения вынесены в `src/systems/WorldClock.js` — `advanceWorld()`, одно правило для игры и тестов). Запрос длится доли секунды.
- **`flush()` — барьер, а не «догонялки»:** `true` значит «на сервере всё, что было изменено до вызова». Не больше двух запросов (повтор потерянной отправки с тем же `id` + текущее состояние); изменения, сделанные во время запроса, кладутся поверх ответа и уходят обычным автосохранением. Перед действием — не больше одного `sync_player`, затем `rpc/player_action`.
- **Причины ошибок разделены:** `network` — только настоящая потеря связи (ошибка `fetch`, таймаут, статус offline); ответ сервера 4xx/5xx или отказ в сохранении — `server` с `error: { rpc, code, status, detail }`; оставшиеся после успешной синхронизации свежие изменения ошибкой не считаются.
- **Сообщения:** «Нет связи с сервером…» — только при `network`; ошибка сервера — «Ошибка сервера: … Попробуйте ещё раз.»; техническая причина пишется в консоль (`console.error`), а с `?debug` — и на экран (RPC, HTTP-статус, код).

## v0.10.3 — ходьба по тапу в обход препятствий

Раньше тап по миру вёл героиню по прямой: она упиралась в дерево, камень или стену и продолжала «идти» на месте. Теперь:

- **Маршрут в обход** (`src/world/nav.js`): поиск пути A* по сетке проходимости (шаг 8 px, запас на ширину тела; узкие проёмы проходятся и без запаса) и выпрямление пути. Сетка строится по живым препятствиям сцены и пересобирается, только когда они меняются (сдвинули камень, убрали корни).
- **Закрытая цель** (внутри препятствия, за стеной, за закрытыми воротами): героиня идёт к ближайшей доступной точке и останавливается; метка ложится туда и краснеет, появляется подсказка «Сюда не пройти». Тап по объекту, к которому нельзя подойти вплотную, срабатывает, если путь привёл в зону взаимодействия.
- **Анимация**: шаги и ходьба идут по фактической скорости, а не по команде. Упёрлись в стену — героиня стоит, повёрнутая к ней, а не топает на месте. Скорость плавно набирается и гасится (около 0,08 с).
- **Управление:** радиус джойстика 70 → 90 и мягкая кривая отклика (меньше «чувствительности» у центра); клик мышью засчитывается до 400 мс (было 260) и со сдвигом до 20 px.
- Тесты: `tests/nav-test.mjs` (обход, закрытые цели, узкие проёмы, 120 случайных тапов по реальному миру; входит в `npm test`).
