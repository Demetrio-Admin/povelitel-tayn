# Восстановление итога боя

Статус — предложение для отдельного согласования. Применяется к основной онлайн-игре, включая дуэли. Баланс и правила боя остаются действующими.

Сейчас Edge сначала проверяет запись, затем вызывает `combat_apply`. Этот вызов атомарно изменяет прогресс и закрывает бой. Если ответ потерялся, повтор видит закрытый контекст, а игрок получает сообщение об отклонении.

## Предлагаемый контракт

- Сервер назначает случайный `combat_id` при начале боя и привязывает его к `user_id`. Клиент может хранить идентификатор последнего отправленного боя для текущего аккаунта после перезагрузки.
- В той же транзакции, где фиксируется прогресс, хранится результат по паре `user_id` и `combat_id`. Результат включает исход, выданные награды, потери и изменения рейтинга, нужные для окна боя. Запись всех действий и полная копия профиля в таблицу результатов не входят.
- Повтор отправки или запрос результата по этому ID возвращает сохранённый итог и актуальную ревизию героя. Одновременные запросы не меняют награду и не показывают результат чужого или другого активного боя. При отсутствии записи сервер возвращает отдельный статус. Клиент не объявляет начисление или окончательный отказ при неизвестном исходе.
- Предлагаемый срок хранения — **7 суток**. Очистка удаляет только записи о завершённых боях. Миграция применяется после проверки срока, объёма и механизма очистки на тестовой базе.
- SQL сохраняет административную обёртку и журнал. Старые клиенты и уже открытые контексты без нового ID завершаются по прежнему протоколу. SQL и Edge выпускаются перед клиентом после проверки совместимости на тестовой базе.

## Приёмка

Проверить потерю первого ответа после успешной записи, параллельный повтор, перезагрузку и запрос с другого устройства того же игрока. Сверить опыт, инвентарь, валюту и журнал до и после. Проверить запрос с другим аккаунтом, другой активный бой, старый контекст без ID и просроченный результат. Для всех режимов итог подтверждается один раз.
